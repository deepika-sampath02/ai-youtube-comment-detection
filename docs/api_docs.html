SafeComment AI API

Send a comment, get back what kind of content it is, how severe it is, and what the platform should do about it. A human reviewer confirms serious incidents; the system never files a report with any authority.

Getting started

Base URL when running locally: http://127.0.0.1:8000/api. All request and response bodies are JSON, except the report download, which is plain text.

curl.exe -X POST http://127.0.0.1:8000/api/moderate/ ^
  -H "Content-Type: application/json" ^
  -d "{\"comment\": \"You are an idiot\", \"platform\": \"instagram\", \"user_id\": \"troll_99\"}"

That command is for Windows Command Prompt. In PowerShell, put the JSON in a file and use -d "@body.json" to avoid quoting problems.

Authentication

If the environment variable SAFECOMMENT_API_KEY is set on the server, every endpoint except /health/ requires the same value in an X-API-Key header. If it is not set, no key is needed. The dashboard's dev server adds the header for you.

X-API-Key: your-key-here

A missing or wrong key returns 401 with {"error": "invalid or missing API key"}.

GET/health/

Checks that the server is running. No key needed.

{"status": "ok"}

Moderate a comment

POST/moderate/

Analyzes one comment, decides an action, and saves the result. If the action is REMOVE, an incident is opened for human review.

FieldRequiredDescription
commentyesThe text to check. Up to 1000 characters.
platformnoinstagram, facebook, youtube, twitter or custom. Anything else is stored as custom.
user_idnoThe commenter's ID on your platform. Needed for strike counting across comments.
comment_idnoYour own ID for the comment, so you can match results back.

Example response (values are illustrative):

{
  "comment": "I know where you live",
  "categories": ["Threat"],
  "severity": "HIGH",
  "needs_review": false,
  "scores": { "threat": 0.93, "...": 0.0 },
  "action": "REMOVE",
  "escalate": true,
  "report_required": false,
  "restrict_user": false,
  "strikes": 2,
  "incident_id": 10
}

incident_id is null unless the action is REMOVE. The exact keys inside scores come from the model; read them from a live response.

Moderate many comments

POST/moderate-batch/

Same analysis for up to 100 comments in one call. Results come back in the same order as the input, but empty comments are skipped, so match by comment_id if you might send blanks.

{
  "platform": "youtube",
  "comments": [
    { "comment": "Please make a part 2", "user_id": "nina_b", "comment_id": "c1" },
    { "comment": "Stop posting this garbage", "user_id": "anon_x7", "comment_id": "c2" }
  ]
}

Each item can also be a plain string, in which case it has no user or comment ID. The response is {"results": [ ... ]}, where each entry has the fields shown above.

History

GET/history/

Every analyzed comment, newest first. All filters are optional query parameters.

ParameterExampleEffect
severityHIGHOne of NONE, LOW, MEDIUM, HIGH, CRITICAL.
categoryThreatMatches any category containing this text.
platforminstagramOnly that platform.
user_idtroll_99Only that user's comments.
actionREMOVEThe decided action, such as ALLOW, WARN or REMOVE.
review1Only comments that need human review.
limit100Rows to return. Default 50, maximum 200.

Response: {"count": N, "results": [ ... ]}. count is the total matching rows, which can be larger than the rows returned.

List incidents

GET/incidents/

Comments that were removed and so need a human decision. Returns up to 100.

ParameterExampleEffect
statusopenopen, confirmed or dismissed. Leave out for all.
cybercrime1Only incidents flagged as possible cybercrime.

Review an incident

POST/incidents/{id}/review/

Records a human decision on an incident.

{ "decision": "confirmed", "reviewer": "Deepika" }
FieldRequiredDescription
decisionyesconfirmed or dismissed.
revieweryesThe reviewer's name, up to 100 characters. It is saved with a timestamp.

Returns the updated incident. An unknown ID returns 404.

Download a report

GET/incidents/{id}/report/

Returns a plain-text evidence file named incident_{id}_report.txt: the comment, the AI scores, the strike count, and who confirmed it and when. It only works for incidents that are flagged as possible cybercrime and confirmed by a reviewer.

StatusMeaning
200The file is returned.
400Not flagged as possible cybercrime, or not yet confirmed. The error message says which.
404No such incident.
The system never submits anything to a government portal. The file tells the reviewer to file the complaint themselves at cybercrime.gov.in and to keep screenshots from the original app.

Result fields

FieldMeaning
categoriesOne or more of Normal, Offensive, Harassment, Threat, Sexual / 18+.
severityNONE, LOW, MEDIUM, HIGH or CRITICAL.
needs_reviewThe model was unsure; a person should look.
confidence0 to 1. Stored with history rows.
scoresPer-category scores from 0 to 1.
actionWhat the platform should do, such as ALLOW, WARN or REMOVE.
escalateWhether the case should go to a senior reviewer.
report_requiredPossible cybercrime. Enables the report download after confirmation.
restrict_userThe user has enough strikes that restricting them is advised.
strikesThis user's earlier non-allowed comments, including this one.
statusnone (no incident), open, confirmed or dismissed.
reviewed_by, reviewed_atWho made the human decision and when (UTC).
Strikes only count when you send a user_id. Without it, every comment starts from zero.

Errors

Errors are JSON in the form {"error": "message"}.

StatusMessage
400Invalid JSON; comment is required; comment is too long; decision must be 'confirmed' or 'dismissed'; reviewer is required.
401invalid or missing API key
404incident not found
405Wrong HTTP method for the endpoint (for example GET on /moderate/).

Limits and accuracy

  • Comments are limited to 1000 characters; batches to 100 comments.
  • The model judges one comment at a time. On a hand-written test of 41 comments it scored 61.0%. It missed most repeated-contact harassment, veiled threats and soft sexual requests.
  • Treat results as a triage aid. A person should make every final decision.
